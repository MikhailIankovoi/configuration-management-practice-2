# Визуализатор зависимостей пакетов Alpine Linux

Практическая работа №2 по дисциплине
«Конфигурационное управление».

Вариант 29.

## Описание

Программа предназначена для получения, анализа и
визуализации зависимостей пакетов Alpine Linux.

Используемый язык программирования — Python.

Проект предусматривает:
- Чтение конфигурации из YAML-файла.
- Получение информации из APK-репозитория.
- Извлечение прямых зависимостей пакетов.
- Построение графа зависимостей рекурсивным BFS.
- Обработку циклических зависимостей.
- Поиск обратных зависимостей.
- Тестовый режим с локальным графом.
- Визуализацию графа в формате Mermaid.

## Реализованные этапы

### Этап 1. Конфигурация

- Загрузка параметров из config.yaml.
- Проверка названия и версии пакета.
- Проверка адреса репозитория.
- Проверка тестового режима.
- Обработка ошибок конфигурации.

### Этап 2. Получение зависимостей

- Скачивание архива APKINDEX.tar.gz.
- Извлечение APKINDEX из архива.
- Разбор записей индекса.
- Поиск пакета по названию и версии.
- Извлечение прямых зависимостей.
- Обработка сетевых ошибок и ошибок архива.

Данные о зависимостях обрабатываются самостоятельно,
без использования пакетных менеджеров.

Этапы 3–5 находятся в разработке.

## Требования

- Python 3.10 или новее.
- Библиотека PyYAML.
- Интернет для работы с реальными APK-репозиториями.

## Установка

Клонировать репозиторий:

    git clone https://github.com/MikhailIankovoi/configuration-management-practice-2.git

Перейти в папку проекта:

    cd configuration-management-practice-2

Установить зависимости:

    py -m pip install -r requirements.txt

## Конфигурация

Настройки находятся в файле config.yaml.

Пример:

    package_name: 7zip
    version: "24.09-r0"
    repository: "https://mirror.opensource.iu.edu/alpine/v3.22/main/x86_64"
    test_mode: false

Параметры:
- package_name — название пакета.
- version — версия пакета.
- repository — URL репозитория или путь к тестовому файлу.
- test_mode — включение тестового режима (true/false).

Тестовый режим будет реализован на третьем этапе.

Указанная версия 7zip используется как пример.
При изменении репозитория версия пакета может отличаться.

## Запуск

На Windows:

    .\run.bat

Либо непосредственно через Python:

    py src/main.py

## Пример работы

    Пакет: 7zip
    Версия: 24.09-r0
    Прямые зависимости:
    - so:libc.musl-x86_64.so.1
    - so:libgcc_s.so.1
    - so:libstdc++.so.6

Зависимости с префиксом so: обозначают
требования к разделяемым библиотекам.

На втором этапе программа извлекает записи зависимостей.
Разрешение зависимостей и построение полного графа
будут реализованы на следующих этапах.

## Тестирование

Для автоматического тестирования используется pytest.

Тестовые функции оформлены в стиле snake_case.
Названия всех тестов начинаются с test_.

Запуск тестов:

    py -m pytest tests -v

Проверяются:
- YAML-конфигурация и обработка ошибок.
- Извлечение прямых зависимостей.
- Поиск пакетов и версий.
- Скачивание и распаковка APKINDEX.
- Ошибки сети и повреждённые архивы.

Всего реализован 21 автоматический тест.
Тесты не требуют подключения к интернету.

## Структура проекта

- src/main.py — точка входа.
- src/config.py — чтение и проверка конфигурации.
- src/repository.py — загрузка APKINDEX.
- src/apk_index.py — разбор индекса и поиск зависимостей.
- tests/test_config.py — тесты конфигурации.
- tests/test_repository.py — тесты загрузки индекса.
- tests/test_apk_index.py — тесты поиска зависимостей.
- config.yaml — настройки программы.
- requirements.txt — зависимости Python.
- run.bat — запуск программы на Windows.
